# NTP 展品

署名：**祀（岁家老十三）**。

规范：RFC 5905（NTPv4）；SNTP 见 RFC 4330。成熟实现优先使用 ntpd、chrony 或 openntpd，不重写 daemon。

## 一次交换在测什么

客户端和服务器交换四个时间戳：T1（客户端发送）、T2（服务器收到）、T3（服务器发回）、T4（客户端收到）。由此可以同时估出网络往返延迟与时钟差：

```text
delay  ≈ (T4-T1) - (T3-T2)
offset ≈ [(T2-T1) + (T3-T4)] / 2
```

关键在于：NTP 不是"服务器说几点你就拨表"，而是把"网络延迟"和"钟差"分离估计。offset 公式假设上下行延迟对称；不对称路径（上下行路由不同）会把路径不对称直接折算成对不齐的钟差，这是 NTP 毫秒级精度上限的主要来源之一。

## 层级与信任

NTP 用 stratum 表示离参考钟的距离：stratum 0 是 GPS/原子钟等参考源，stratum 1 服务器直接接参考源，往下逐层 +1。stratum 16 表示未同步。公共 pool（如 pool.ntp.org）的信任模型是"多数派":客户端询多个源,踢掉明显离群的,再组合。历史上 NTP 的安全研究(monlist/DRDoS 放大、off-path 时间偏移攻击)都围绕"把时间当事实接受"这个隐含假设展开。

## 与 PTP 的边界

PTP（IEEE 1588）把打时间戳下沉到网卡/交换机硬件，排除 OS 调度延迟,做到亚微秒;NTP 停在软件时间戳,毫秒到几十毫秒。机房里"不起眼的 1U 盒子"通常是 GPS 授时的 stratum 1 服务器,给整个机房提供统一时刻。
